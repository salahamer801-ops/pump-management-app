# مشروع تنظيم المضخات

تطبيق عربي (RTL) لإدارة المضخات والدياليات والحصص المائية اليومية، بواجهة موبايل أولًا — دفتر شخصي للمساهم، ولوحة تشغيل كاملة لصاحب المضخة، ولوحة مستقلة لمسؤول النظام.

> **الحالة:** المرحلة الثانية مكتملة — بيانات التشغيل والحسابات صارت على الخادم مع قاعدة بيانات PostgreSQL، والواجهة تصل إليها عبر مسار نسبي واحد `/api`. التفاصيل الكاملة في [`docs/phase2-backend-migration.md`](docs/phase2-backend-migration.md).

---

## البنية

```mermaid
flowchart LR
  U["المستخدم — متصفح أو جوال"] -->|"GET / · /login · أي صفحة"| W["الواجهة: React + Vite + Tailwind (dist)"]
  U -->|"طلبات /api (نسبية)"| A["الخادم: Express"]
  W -.->|"الخدمة نفسها"| A
  A -->|"SQL"| P[("PostgreSQL")]
```

**خدمة واحدة، رابط واحد:** الـ`Dockerfile` يبني الواجهة ثم يشغّلها مع الـAPI من نفس العملية والمنفذ — `GET /login` يعيد التطبيق و`GET /api/...` يذهب إلى Express. هذا يعني عدم الحاجة إلى دومينين أو CORS أو وسيط يمرّر الطلبات (`UPSTREAM_API_BASE` غير مستخدم في المشروع إطلاقًا). في المعاينة تعمل الواجهة والخادم كخدمتين لتسهيل التطوير، وفي النشر يكفيهما الرابط نفسه.

## أوضاع الاستخدام

| الوضع | لمن | المدخل |
|---|---|---|
| **حساب على الخادم** | صاحب المضخة (مالك/مدير) أو المساهم | الشاشة الأولى: دخول · حساب جديد · نسيت كلمة المرور |
| **لوحة مسؤول النظام** | من يدير المستخدمين والمضخات والعضويات | تُفتح من تطبيق المسؤول |

> لا يوجد تسجيل حساب محلي في المتصفح: كل حساب يُنشأ على الخادم (رقم هاتف + كلمة مرور)، والصلاحيات تُفحص على الخادم لا في الواجهة.

## أين تُحفظ بيانات التشغيل

PostgreSQL هو المصدر الرسمي، ويُخزَّن الجهاز نسخة محلية تعمل بلا إنترنت:

| الحالة | ما يحدث عند فتح التطبيق |
|---|---|
| الجهاز فيه بيانات، والخادم فارغ | تُرفع بيانات الجهاز إلى الخادم مرة واحدة (مع نسخة احتياطية محلية قبل الرفع، وبلا حذف أي شيء) |
| الخادم فيه بيانات | تُنزَّل بيانات الخادم إلى الجهاز (بنسخة احتياطية محلية قبل الاستبدال) |
| جهاز جديد على مضخة مسجّلة | تُبنى المضخة وبياناتها من الخادم مباشرة — لا يُطلب تسجيل مضخة جديدة |
| لا إنترنت | يعمل التطبيق محليًا، وتُرفع التعديلات عند عودة الاتصال |

- المخزن يرتبط بـ **معرّف المضخة على الخادم** الذي يأتي من قائمة مضخات الحساب، لا بأي رقم محلي قديم.
- كل تعديل رسمي يُرفع بعد ثوانٍ (`PUT /api/pumps/:id/operating`)، والمزامنة الأولى تُعلَّم بـ `POST …/migrate-local`.
- حالة الحفظ ظاهرة أعلى الشاشة: «محفوظ على الخادم» · «جارٍ الحفظ…» · «لا يوجد اتصال بالإنترنت».
- المساهم يقرأ البيانات الرسمية للمضخات المعتمدة له من الخادم (قراءة فقط) على أي جهاز.

## المزايا

**وضع المالك / المدير**
- إعدادات المضخة التشغيلية: البئر، المزرعة، المحرك، الطاقة، ساعات التشغيل، سعر الديزل، الرواسة، وحدة الحصة والعملة.
- **مضخة واحدة هي الأصل**: المسؤول يدير مضخته من لوحة واحدة، وإن احتاج مضخة ثانية فالطريق الوحيد هو **مفتاح المضخات** الصغير داخل الإعدادات (إنشاء مضخة أخرى أو التبديل بينهما).
- الديالات: الرقم، البداية، عدد الأيام، الحالة، وتثبيت كشف الدوام أو إعادة فتحه.
- كشف مساهمي الديالة (نصيب بالدقائق لكل عضو) **مرجع واحد** يُدار في شاشة الديالات، ويُعرض في شاشة اليوم للقراءة فقط: لا يُعدَّل من هناك ولا **يحجز** أي ساعة تلقائيًا.
- **الدوام الفعلي** لهذا اليوم يُبنى مشاركًا مشاركًا: نافذة واحدة تُدخل الاسم والوقت («من … إلى …») والمدة، مع الديزل (مسدد/نقص/غير مسدد) والرواسة (نقد/أجل/جزء نقد وجزء أجل) وسبب النقص عند تقليل النصيب — والترتيب الزمني إلزامي (لا تداخل ولا خروج عن نافذة التشغيل) في الواجهة وفي المخزن.
- الدوام الفعلي اليومي، الاستخدام، الوقود (ساعات/لتر/ساعة/النقص/السعر)، الرواسة/المشغّل، التوقفات (عطل، مطر، وقود، طارئ…).
- المالية: الدفعات، الديون، الحركات والتكاليف، مع لقطات (snapshot) للأسعار وقت كل عملية.
- الناس والمساهمون، التقارير، وسجل تدقيق لكل عملية حساسة.

**وضع المساهم**
- دفتر شخصي لعدة مضخات: الدورات، الأدوار، توزيع الحصص اليومية بالدقائق والساعات، الوقود والرواسة، والتقارير.
- سجلات شخصية خاصة لا تختلط ببيانات المضخة الرسمية.
- مزامنة رسمية للبيانات المعتمدة من صاحب المضخة.

**لوحة مسؤول النظام**
- المستخدمون (تعيين، إعادة كلمة المرور، كشف الهاتف بصلاحية)، المضخات، العضويات والطلبات، سجل التدقيق، وإعدادات عامة للتطبيق.

**عام**
- عربي كامل مع RTL، وهوية بصرية كحلية (`#032a4c`) مع لوحة ألوان متنوّعة للأقسام، وإدخال أرقام موحّد في كل الحقول.
- **الوقت بصيغة 12 ساعة عربية** في كل الشاشات والحقول (`6:00 ص` · `3:30 م`) — دالة واحدة `formatTimeAmPm` في `src/domain/util.ts`، والتخزين يبقى 24 ساعة (`HH:MM`).
- **النطاقات الزمنية تُكتب من اليمين إلى اليسار**: `formatTimeRange` تُنتج `6:00 ص ← 9:00 ص` (البداية على اليمين، والسهم يشير إلى النهاية في اتجاه القراءة العربية) — بما في ذلك رسائل التداخل والتنبيهات.
- يعمل دون اتصال ويمكن تثبيته كتطبيق (PWA).
- **المصادقة والتصريح على الخادم** — لا في الواجهة.

## التشغيل محليًا

**المتطلبات:** Node.js ≥ 20، وقاعدة PostgreSQL (رابط اتصال).

**1) الواجهة**

```bash
npm install
npm run dev          # يفتح Vite على المنفذ 5173، ويحوّل /api تلقائيًا إلى الخادم
```

**2) الخادم (طرفية ثانية)**

```bash
cd server
npm install
DATABASE_URL="postgresql://..." PORT=3001 node src/index.js
```

عند الإقلاع ينشئ الخادم الجداول الناقصة تلقائيًا (`IF NOT EXISTS`) — **لا يُحذف أي جدول أو عمود ولا تُفقد بيانات**، ثم يصبح جاهزًا على `/api`.

**متغيرات البيئة:** `DATABASE_URL` (مطلوب) و`PORT` (اختياري، الافتراضي 3001). لا تُكتب أي أسرار في الكود أو في المستودع.

**فحوصات سريعة:**

```bash
npm run verify                          # فحص منطق الحسابات (بلا خادم)
node scripts/verify-phase2-api.mjs      # فحص المرحلة الثانية (يحتاج الخادم يعمل)
curl http://localhost:3001/api/health   # {"ok":true,"service":"pump-api"}
```

## البناء والنشر

**خدمة واحدة تخدم كل شيء:** `Dockerfile` واحد يبني الواجهة ثم يشغّل Express، فيخرج الرابط نفسه:

| المسار | ما يخدمه |
|---|---|
| `GET /` | تطبيق React المبنى (`dist/index.html`) |
| `GET /login` · `/dashboard` · أي مسار واجهة | نفس `dist/index.html` (SPA fallback) — لا 404 |
| `GET /api/...` | واجهة البرمجة (Express) على القاعدة نفسها |

- **مرحلتان في صورة واحدة:** المرحلة الأولى `node:20-alpine` تثبّت اعتماديات الواجهة وتنفّذ `npm run build`، والمرحلة الثانية صورة تشغيل خفيفة فيها اعتماديات الخادم للإنتاج فقط + كود الخادم + `dist` المبنى.
- **مسار `dist` بلا افتراضات:** الخادم يبحث عن الواجهة المبنية في `../dist` ثم `../../dist` ثم `./dist` بالنسبة لموقعه هو (لا يعتمد على مجلد التشغيل الحالي)، فإن لم يجدها يعمل كـAPI فقط بلا فشل.
- **منفذ واحد:** `process.env.PORT` فقط (لا رقم ثابت في الكود) ولا يُكتب أي دومين أو رابط داخل الكود.
- **الواجهة تصل إلى خادمها بـ`/api` من نفس الأصل** — لا CORS بين دومينين، ولا `UPSTREAM_API_BASE`، ولا وسيط يمرّر الطلبات.
- **لا كاش للصفحة والعامل الخدمي** (`index.html` · `sw.js` · `push-sw.js` · بيان التطبيق) و**كاش طويل للأصول ذات البصمة** — فلا يتجمّد التطبيق على نسخة قديمة، ويظهر شريط «نسخة جديدة متاحة».

### النشر على استضافة الخادم (Railway)

1. اربط خدمة واحدة بمستودع المشروع على `main` — Railway يبني من `Dockerfile` تلقائيًا عند كل رفع.
2. متغيّرات البيئة: **`DATABASE_URL`** فقط (المنفذ `PORT` يمرّره المزوّد تلقائيًا). لا تُكتب أي قيمة في الكود.
3. فحص الصحة بعد النشر:

```bash
curl https://<نطاق-الخدمة>/api/health      # {"ok":true,"service":"pump-api"}
curl https://<نطاق-الخدمة>/api/health/db   # {"ok":true,"db":"..."} — يتأكد من قاعدة البيانات
curl -I https://<نطاق-الخدمة>/login        # 200 text/html — الصفحة تعمل عند فتحها مباشرة
```

### الاستضافة على المنصة (Mythex)

نفس `Dockerfile` يعمل كما هو: خدمة الواجهة موقع ثابت من `dist`، وخدمة الخادم صورة من `Dockerfile`؛ نطاق التطبيق يولّد `/api` إلى خدمة الخادم، فيكفي نشر الخدمتين معًا دون ضبط أي رابط.

**بعد كل تعديل في الكود:** أعد النشر لتُبنى الواجهة من جديد وتُشغَّل نسخة الخادم الجديدة. أما تعديلات البيانات فلا تحتاج نشرًا: تُحفظ في قاعدة البيانات فورًا ويراها كل جهاز عند المزامنة.

**ملاحظة تشغيل:** الخادم وقاعدة البيانات ينامان عند الخمول ويستيقظان عند أول زيارة (ربما تأخير ثوانٍ في أول طلب). لا تُفتح اتصالات قاعدة دائمة، وأي طلب يتعامل مع انقطاع الاتصال بإعادة محاولة واحدة.

**الدومين:** يمكن ربط دومين خاص من إعدادات المشروع؛ لا يُكتب أي اسم نطاق داخل الكود.

## التطبيق على الجوال (PWA بدل APK)

لا يتوفّر في المنصة بناء ملف APK أو النشر في متجر تطبيقات (تطبيقات الجوال الأصلية قيد الإعداد). البديل المعتمد هو **تطبيق ويب مثبَّت**:

- **أندرويد/كروم:** زر «ثبّت التطبيق على جوالك» داخل التطبيق (يستفيد من `beforeinstallprompt`)، أو قائمة المتصفح ← «تثبيت التطبيق».
- **آيفون/سفاري:** زر المشاركة ← «إضافة إلى الشاشة الرئيسية».
- يعمل بعد التثبيت ملء الشاشة (بلا شريط متصفح) عبر `manifest.webmanifest` مع أيقونات 192/512/آيفون و`display: standalone`.
- **التحديثات:** يُسجَّل العامل الخدمي نسخة جديدة بالانتظار ويظهر شريط «نسخة جديدة متاحة — أعد التحميل» (`UpdateNotice`) — لا يُعاد تحميل الصفحة فوق عمل المستخدم.
- نداءات `/api` لا تُخدَم من الكاش أبدًا (`navigateFallbackDenylist`) فالبيانات الرسمية من الخادم دائمًا.

## المزامنة: من مسؤول المضخة إلى المساهمين

المبدأ: **الخادم (PostgreSQL) هو المصدر الرسمي**، وجهاز المساهم نسخة عرض مؤقتة.

| الاتجاه | متى |
|---|---|
| المسؤول ← الخادم | تلقائيًا بعد كل تعديل رسمي (بتأخير ~2.5 ثانية) |
| الخادم ← جهاز المساهم | عند فتح التطبيق، عند العودة إليه من الخلفية، كل 60 ثانية وهو مفتوح، عند عودة الشبكة، وعند زر «تحديث» أو السحب للأسفل |
| الصلاحية | الربط برقم تعريف المضخة (`PMP-XXXXXX`) ثم موافقة المسؤول؛ ولا يملك المساهم أي تعديل |

**اقتصاد النداءات:** قبل أي تنزيل كامل يسأل الجهاز `GET /api/pumps/:id/operating/version` (رقم النسخة ووقت آخر رفع فقط)، ولا ينزّل شيئًا إن كانت النسخة نفسها.

**التنبيهات:** إشعارات المسؤول تُرفع مع بيانات التشغيل (`extra.notifications`) فتصل المساهم على أي جهاز، و«جديد» **علم شخصي على الخادم**: `POST /api/pumps/:id/notifications/read` يعلّمها مقروءة له وحده (`notification_reads`) ولا يمسّ سجل المسؤول.

**مؤشرات الوضوح:** سطر «آخر تحديث» وحالة الاتصال في الرئيسية، وبطاقة «المزامنة مع المسؤول» في الإعدادات (حالة الخادم + آخر تحديث + زر تحديث الآن).

### الإشعارات الفورية على الجوال (Web Push)

يصلك على الجوال إشعار **لحظة** حفظ المسؤول لأي تعديل — بلا مهام مجدولة: يُرسَل داخل الطلب الوارد نفسه (طلب الحفظ)، فإن لم يعدّل المسؤول شيئًا فلا إشعارات أصلًا.

- **التفعيل:** من إعدادات المساهم ← «إشعارات الجوال» ← «فعّل الإشعارات على هذا الجوال» (إذن واحد).
- **الشرط:** التطبيق مثبَّتًا على الشاشة الرئيسية، وكروم على أندرويد أو سفاري على آيفون (iOS 16.4+).
- **ما يُرسَل:** الإشعارات الجديدة التي يكتبها المسؤول بنصّها، وإلا إشعار عام «المسؤول حدّث بيانات المضخة» بفاصل لا يقل عن ١٠ دقائق (بلا إزعاج).
- **المفاتيح:** تُولَّد مفاتيح VAPID مرة واحدة لهذا المشروع وتُحفظ في قاعدة بياناته (`app_settings`) — لا تُكتب في الكود ولا في المستودع.
- **الخادم:** `server/src/push.js` (الإرسال وتنظيف الاشتراكات الميتة)، والجداول `push_subscriptions` و`notification_reads`، وعميل الإشعارات `public/push-sw.js` يُستورد داخل العامل الخدمي (`importScripts`).
- **الخصوصية:** الإشعار يحمل عنوانًا ونصًّا ورابطًا للتطبيق فقط، ولا يُنقل أي بيانات تشغيل في الإشعار.
- فشل الإرسال لا يُفشل الحفظ أبدًا: يُسجَّل ويُتجاهَل، وتُحذف الاشتراكات المنتهية (404/410).

| `public/icons/apple-touch-icon.png` | أيقونة آيفون |
| `public/icons/icon-512-maskable.png` | أيقونة أندرويد التكيّفية (الشعار داخل المنطقة الآمنة) |

**عند تغيير الشعار:** ضع الصورة الجديدة مكان `brand/app-icon-source.png` ثم شغّل:

```bash
node scripts/gen-icons.mjs --from-brand
```

(يحتاج ImageMagick — يُستخدم عند إعداد الشعار فقط، لا في كل بناء.) السكربت يقتطع مربّع
الشعار من الصورة تلقائيًا (`scripts/artwork-box.mjs`)، يضع زوايا دائرية على خلفية هوية
التطبيق `#032a4c`، ويشتقّ الأيقونات الأربعة. الأيقونات الموجودة تبقى كما هي في البناء
العادي فلا تُستبدل بغيرها.
